Template guide

Design your own bill

A template is one HTML file. Write your layout, put {{placeholders}} where the details go, and the app turns them into a form, does the maths, and prints your design exactly.

Quick start

The fastest way is to start from a template that already works and change it.

  1. Get a starting file. In the app, open Templates and press Download on a built-in template, or copy one from the playground below.
  2. Edit it in any text editor. Change the layout and colours, and add or rename placeholders.
  3. Upload it. Templates > Upload .html. The app shows a report of every field it found and anything it removed, before you save.
  4. Use it. Pick it from the template menu on the Bill page. Uploading a file with the same template name later replaces the saved copy.

You can also edit in the app: Templates > New from Classic opens an editor with a live preview.

Placeholders

Write {{field_name}} anywhere in your text and the app adds a form field for it. Use lowercase words joined by underscores. The label comes from the name, so {{customer_name}} becomes Customer name.

Values are always inserted as plain text, never as HTML. Line breaks in addresses and notes become line breaks on the bill.

The name picks the input type

If the name The input is Example
ends with _date Date picker due_date
ends with _address, _notes, _terms Multi-line text customer_address
ends with _phone Phone number business_phone
ends with _email Email customer_email
ends with _logo, _image, _signature Image upload business_logo
is tax_rate or tax_<name>_rate, or ends with _percent Percentage tax_cgst_rate
contains price, amount, charge, rate, discount, or ends with _paid Money advance_paid
is item.qty Number item.qty
anything else Single-line text vehicle_number

A number at the end is ignored, so business_phone_2 is still a phone field.

The prefix picks the form section

business_Business details. Filled in from your saved business profile.
customer_Customer / Bill to
invoice_Invoice details
item.Items, one set per row
tax_Tax
anything elseOther

Item rows

Put data-repeat="items" on the element that should repeat once per item, usually a table row. Inside it, use {{item.<field>}}. 

<tr data-repeat="items">
  <td>{{item.index}}</td>
  <td>{{item.description}}</td>
  <td>{{item.qty}} {{item.unit}}</td>
  <td>{{item.price}}</td>
  <td>{{item.total}}</td>
</tr>
# Item Qty Price Total
1 Jaggery 3,300 kg ₹90.00 ₹2,97,000.00
2 Cashew W240 25 kg ₹980.00 ₹24,500.00

Standard item fields are description, qty, unit, price and hsn. Any other item. name, like item.batch, becomes an extra box in each item row. item.total and item.index are filled in for you.

Tables are strict.

Inside a <table>, put placeholders inside a <td> or <th>. Text placed directly in <table>, <tbody> or <tr> is moved out of the table by the browser.

Show and hide

Add data-if="field_name" to an element and it only appears when that field has a value. Start the name with ! to do the opposite.

Only when filled

<p data-if="business_gstin">
  GSTIN: {{business_gstin}}
</p>

No GSTIN entered? The whole line disappears, label included.

Only when empty

<p data-if="!customer_name">
  Cash sale
</p>

Shows "Cash sale" when no customer name is given.

Inside item rows

<span data-if="item.hsn">
  HSN {{item.hsn}}
</span>

Checked separately for each row.

Calculated fields

These are filled in by the app and never appear in the form. Use them anywhere in your template.

Placeholder Value
{{item.total}} price × qty for that row
{{item.index}} row number: 1, 2, 3
{{subtotal}} sum of all item totals
{{tax_<name>_amount}} subtotal × tax_<name>_rate ÷ 100, so tax_cgst_rate gives tax_cgst_amount
{{tax_amount}} subtotal × tax_rate ÷ 100, plus every tax_<name>_amount
{{grand_total}} subtotal + tax + every _charges field − every _discount field
{{total_in_words}} grand total in words, e.g. Three Lakh Thirteen Thousand Rupees Only
{{balance_due}} grand total − every _paid field

Charges, discounts and advance payments

The ending of a field's name tells the app what to do with the amount.

_chargesadded to the total, e.g. transport_charges
_discounttaken off the total, e.g. invoice_discount
_paidalready received; taken off to give the balance, e.g. advance_paid

Worked example: 3,300 kg jaggery at ₹90/kg

{{subtotal}}₹2,97,000.00
{{transport_charges}}+ ₹16,000.00
{{grand_total}}₹3,13,000.00
{{advance_paid}}− ₹81,000.00
{{balance_due}}₹2,32,000.00
  • Charges only fill their own placeholder and add to the total. They never become item rows.
  • {{subtotal}} stays filled when charges are set, so you can show Subtotal, then the charge, then the total.
  • Wrap the advance and balance lines in data-if="advance_paid" so they only appear when an advance was paid.
  • Rates are shown as plain numbers, so write the percent sign yourself: Tax ({{tax_rate}}%).

Images and CSS

Logos and signatures

<img src="{{business_logo}}" alt="">

The placeholder must be the whole src. The user uploads the image in the form. Fixed images in your design must be embedded as data:image/....

Colours from a field

:root { --accent: {{accent_color}}; }
h1 { color: var(--accent); }

In CSS, placeholders only work inside custom properties like --accent. Anywhere else they are dropped.

Put all CSS in one <style> tag in <head>. Use system fonts such as system-ui, "Segoe UI", Roboto, Arial, sans-serif, or embed a font file as a data: URI in @font-face. Fonts from the internet do not load. Inline SVG drawings work well for logos and icons.

Page size

Declare the paper size with @page. Without it, the bill is A4.

  • Receipts need an explicit height. size: 80mm auto is not valid CSS.
  • Set the page margins as padding on body, and keep @page margin at 0.
  • Add print-color-adjust: exact; to body so background colours print.
  • Add tr { break-inside: avoid; } so item rows never split across two pages.

Labels and defaults

One optional JSON block names your template and sets labels, input types, default values and field order. It is only read as data, never run. 

<script type="application/json" id="template-meta">
{
  "name": "My Invoice",
  "version": "1.0",
  "fields": {
    "invoice_number": { "label": "Invoice #", "default": "INV-001" },
    "footer_note": { "type": "textarea", "default": "Thank you for your business." },
    "vehicle_number": { "label": "Vehicle no.", "placeholder": "JH 15 AB 1234" }
  }
}
</script>
nameShown in the template menu. Uploading a file with the same name replaces your saved copy.
versionShown when you replace a saved copy, e.g. "version 1.0 to 1.2".
labelText above the input, instead of the name-based label.
defaultFilled in when a new bill starts. Your business profile wins for business_ fields.
typetext, textarea, date, tel, email, image, currency, number or percent.
placeholderGrey hint text inside the empty input.
orderA list of field names at the top level ("order": [...]) sets the order in the form.

Rules and limits

Templates can come from anywhere, so every template is cleaned before use and bills are shown in a locked frame. Anything not allowed is removed and listed in the upload report.

Works

  • Any HTML layout: tables, flexbox, grid
  • CSS in one <style> tag, plus style="" attributes
  • Images and fonts embedded as data: URIs
  • Inline <svg> drawings
  • Links to places in the same page (href="#terms")
  • One file up to 2 MB

Removed

  • JavaScript: <script> and on... attributes
  • Anything loaded from the internet: images, fonts, @import, links
  • Forms, inputs and buttons
  • Iframes, embeds, video and audio
  • <link> and <meta> tags

Before you upload

  • Every placeholder is spelled the way you want its label to read.
  • The item row has data-repeat="items" and the totals use {{grand_total}}.
  • Optional lines (GSTIN, discount, advance) are wrapped in data-if.
  • @page sets your paper size, and a long bill still breaks cleanly between rows.
  • Images and fonts are embedded, not linked.
  • The upload report shows no surprises under Removed by the security filter and no warnings like looks like a typo of {{grand_total}}.
